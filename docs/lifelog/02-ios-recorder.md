# 02. iPhone 常時録音アプリ仕様（仮称: Kioku Recorder）

対象: iOS 26 以降 / iPhone（メイン録音ハード）
配布: App Store 公開はしない。Apple Developer Program の開発用プロビジョニングで自機にインストール

---

## 1. 前提となる iOS の制約（調査済みの事実）

| 項目 | 事実 | 設計への影響 |
|---|---|---|
| 背景録音 | `Info.plist` の `UIBackgroundModes` に `audio` を宣言すれば背景でマイク capture を継続できる | 実現可能 |
| 赤マイクインジケータ | 背景録音中はステータスバーに常時表示され、**隠す手段はない** | 隠せない前提で受容する。むしろ「録っている」ことが可視なのは倫理的に良い |
| 電池 | 常時録音で実測 **34〜50% のバッテリー寿命短縮** 報告あり | 日中の充電が必須。VAD と低電力モード連動で緩和 |
| 端末内 ASR | iOS 26 の `SpeechAnalyzer` / `SpeechTranscriber` は 1分制限とオンライン依存が撤廃され、日本語（ja_JP）オンデバイス対応 | 速報テキストを端末内で作れる |
| 割り込み | 通話・他アプリの音声で `AVAudioSession` が中断される。iOS 13 以降、背景からの録音再開に失敗するケースがある | 中断ハンドラと再起動リトライを必ず実装 |
| 無料プロビジョニング | 有効期限 7 日 | 実質使えない。**Developer Program（年 ¥15,800）加入が前提** |

## 2. 録音仕様

```swift
// AVAudioSession 設定の方針
category: .record  (通話中も録りたいなら .playAndRecord は避ける／要検証)
mode:     .default
options:  [.mixWithOthers, .allowBluetooth, .allowBluetoothA2DP]
```

| 項目 | 値 | 備考 |
|---|---|---|
| サンプルレート | 16 kHz mono | ASR に必要十分。ファイルサイズを抑える |
| コーデック | Opus 24 kbps（`AVAudioFile` で保存後に変換、または Opus 直書き） | 1時間 ≒ 10 MB |
| チャンク長 | 5 分固定 + 無音境界での早期クローズ | 転送単位と障害復旧単位を兼ねる |
| VAD | Silero VAD（Core ML 変換）を推奨。第一段は簡易エネルギー + ゼロ交差でも可 | 無音チャンクは保存せず破棄 |
| 発話前後の padding | 各 2 秒 | 語頭切れを防ぐ |
| 端末内 ASR | `SpeechAnalyzer` を録音と並走。5分チャンクごとに `draft.txt` を出力 | 低電力モード時は停止 |

### 破棄ポリシー（重要）

**「24時間録音」ではなく「取りこぼしゼロの自動録音」を実装する。**
VAD が無音と判定した区間は保存しない。結果として実効録音は 1日 6〜9 時間になり、
電池・ストレージ・Mac の処理負荷がすべて現実的な範囲に収まる。

## 3. 付随メタデータ

チャンクごとに JSON サイドカーを生成する。これが後段の「エピソード分割」と「文脈付け」の精度を決める。

```json
{
  "chunk_id": "c_20260903_140512_ab12",
  "device": "iphone",
  "start": "2026-09-03T14:05:12+09:00",
  "end":   "2026-09-03T14:10:12+09:00",
  "speech_ratio": 0.72,
  "mean_db": -31.4,
  "location": { "lat": 35.68, "lon": 139.76, "accuracy_m": 500, "label": "自宅" },
  "motion": "stationary",
  "bluetooth": "AirPods Pro",
  "focus_mode": "仕事",
  "battery": 0.63,
  "charging": false,
  "draft_transcript": "…端末内 ASR の速報テキスト…"
}
```

| 取得元 | 使い道 |
|---|---|
| `CLLocationManager`（significant location change / 粗い粒度） | 場所ラベル付け、ジオフェンス除外の判定 |
| `CMMotionActivityManager` | 静止 / 歩行 / 自動車 → 「移動中の独り言」の判別 |
| Bluetooth 接続先 | 車載 = 運転中、会議室スピーカー = 会議 |
| Focus モード | 「仕事」中の会話を優先度高に |
| カレンダー（`EKEventStore`, 読み取り） | 予定名をエピソードに紐付ける最強のヒント |

> **位置情報は粗い粒度（500m）で十分**。番地レベルは不要で、精度を落とすほど電池も持つ。

## 4. UI 設計

### 参考にする既存サービス

| サービス | 参考にする点 |
|---|---|
| **Limitless（旧 Rewind）Lifelog** | 1日を帯で表す**タイムライン**、会話ブロックのカード表示、日次サマリ、Ask AI の入口 |
| **Granola** | 会議ノートの「要約が主、全文は折りたたみ」というレイアウト |
| **Day One** | 日付ナビゲーションと、その日の出来事の一覧性 |
| **Voice Memos（純正）** | 波形表示と録音中の安心感。ここは真似すべき |
| **Plaud / Omi アプリ** | 「重要マーク」のワンタップ操作、デバイス状態（電池・同期）の常時可視化 |

### 画面構成（4タブ）

```
┌─────────────────────────────────┐
│  ● 録音中  14:05〜  電池63%  ↑3 │  ← 常時ヘッダ（状態が一目でわかる）
├─────────────────────────────────┤
│                                 │
│   [ 今日 ] 9月3日(木)            │
│                                 │
│   ▓▓▓░░▓▓▓▓▓░░░░▓▓░░░▓▓▓▓        │  ← 1日の発話密度の帯
│   6   9   12   15   18   21      │
│                                 │
│   ┌───────────────────────────┐ │
│   │ 14:05-15:02  A社 定例MTG  │ │  ← エピソードカード
│   │ 👤 3人  📍自宅  ⭐️⭐️⭐️    │ │
│   │ 新プランの価格帯について… │ │
│   └───────────────────────────┘ │
│   ┌───────────────────────────┐ │
│   │ 12:30-12:41  移動中のメモ │ │
│   │ 👤 1人  🚗 運転中          │ │
│   └───────────────────────────┘ │
│                                 │
├─────────────────────────────────┤
│  今日  |  検索  |  重要  |  設定 │
└─────────────────────────────────┘
```

#### タブ1「今日」（ホーム）
- 上部に**発話密度の帯グラフ**（1日 24時間を横軸、話していた時間帯が濃い）
- その下にエピソードカードの時系列リスト
- カードをタップ → 速報テキスト（正本が届いていればそちら）、再生、重要マーク、除外指定
- 引っ張って更新 = Mac との同期状況を再確認

#### タブ2「検索」
- 全文検索（端末内の速報テキスト対象）
- フィルタ: 日付 / 人 / 場所 / タグ / 重要度
- 「先週 A社 について話したこと」のような自然文検索は Phase 4 で Mac 側索引に問い合わせる

#### タブ3「重要」
- 重要マークを付けたエピソードだけの一覧
- ここが「後で読み返す」導線の中心。**Phase 0 の価値検証はこの画面が使われるかで判定する**

#### タブ4「設定」
- 録音のオン/オフ、ビットレート、VAD 感度
- 転送方式（Tailscale / iCloud Drive）とエンドポイント
- 除外ジオフェンスの登録（地図から半径指定）
- 除外時間帯（例: 23:00-06:00 は録らない）
- ストレージ管理（未転送チャンクの一覧と手動再送）

### 停止操作（最重要 UI）

**録音を止める操作は、どの画面からでも 1 アクションで届かなければならない。**
「止めたいときに止められない」ことが、この種のアプリが人間関係を壊す唯一の経路。

| 導線 | 実装 |
|---|---|
| アプリ内 | ヘッダの「● 録音中」を長押し → 一時停止メニュー（15分 / 1時間 / 今日はもう録らない / 手動再開まで） |
| ロック画面 | **Live Activity** に録音状態と停止ボタンを常時表示 |
| コントロールセンター | iOS 18 以降の **Control Widget** に「録音停止」を登録 |
| アクションボタン | iPhone 15 Pro 以降の Action Button に割り当て可能（Shortcuts 経由） |
| Apple Watch | コンプリケーションから停止 / 重要マーク（Phase 4） |
| 自動 | 除外ジオフェンス進入 / 除外時間帯 / 「睡眠」Focus モード時は自動停止 |

### 重要マーク（もう一つの中心 UI）

- 「今の会話は後で使う」と思った瞬間に押す。**直近5分 + 以後10分**に `importance: 4` を立てる
- 導線: アプリ内の大ボタン / ホーム画面ウィジェット / Action Button / Watch
- ここで人間が入れる 1bit の情報が、後段のエージェントにとって最も価値の高い教師信号になる

### 録音中の安心感

- 録音中は Live Activity に**経過時間 + 直近の音量メーター**を出す
- 「録れているつもりで録れていなかった」が最悪の失敗なので、**異常時は必ず通知**する
  - マイク権限が落ちた / セッション中断が 3 回連続で復帰失敗 / ストレージ残 1GB 未満 / 未転送チャンクが 200 を超えた / 電池 20% 未満で自動停止した

## 5. 転送仕様

```
[録音完了チャンク] → [転送キュー(SQLite)] → [URLSession background transfer]
                                              ↓
                            POST https://mac.tailnet.ts.net:8443/ingest
                            Authorization: Bearer <device token>
                            multipart: audio.opus + meta.json
                                              ↓
                            201 Created → チャンクを端末から削除
```

- **送信条件（既定）**: 充電中 かつ Wi-Fi。設定で「モバイル通信でも送る」を選べる
- **再送**: 指数バックオフ（2s, 4s, 8s, 16s, 上限 5 分）。無期限にリトライ
- **端末保持**: 転送成功後も 48 時間はローカルに残す（Mac 側の障害に備える）
- **逼迫時**: 残ストレージ 2GB を切ったら古い転送済みチャンクから削除、それでも足りなければ iCloud Drive フォールバックに切替
- **認証**: デバイスごとの長期トークン。Tailscale の ACL でそもそも自分のデバイスしか到達できない

## 6. 電池対策の具体策

| 施策 | 効果 |
|---|---|
| VAD で無音を捨てる（保存もエンコードもしない） | 実効処理量が 1/3 程度に |
| 端末内 ASR は「重要マーク済み」「Focus=仕事」のときだけ全開、それ以外は 15 分バッチ | ASR は録音より重い |
| 低電力モード検知（`ProcessInfo.isLowPowerModeEnabled`）で自動的に端末内 ASR 停止・ビットレート低下 | |
| 位置情報は significant location change のみ（連続測位しない） | GPS 常時測位は録音より電池を食う |
| 電池 20% で録音停止 + 通知 | 「電池切れで肝心なときに動かない」を防ぐ |
| 運用: MagSafe スタンド（デスク）+ 車載充電器 + モバイルバッテリー | **これが実は一番効く。設計より運用** |

> 正直に見積もると、iPhone 単独で丸1日ノー充電の運用は成立しない。
> 「日中どこかで 1 時間充電する」を前提に置く。

## 7. 開発の進め方

### 既存 OSS の流用検討

**Omi**（BasedHardware/omi, オープンソースの AI ウェアラブル）は Flutter 製で、
背景録音・Opus・オフライン録音・チャンク管理が実装済み。フォークして自分用に削るのは現実的な選択肢。

ただし本構想では **iOS 26 の SpeechAnalyzer をネイティブに使いたい**ため、
**SwiftUI でゼロから書く方を推奨**する。必要な機能は絞れば 2〜3週間で書ける規模。
Omi は「実装の答え合わせ」として参照する位置づけにする。

### 実装順（Phase 1 内）

1. 前面での録音 + ファイル保存（最小）
2. 背景モード + セッション中断からの復帰
3. VAD + チャンク分割
4. 転送キュー + Tailscale 送信
5. `SpeechAnalyzer` 統合（速報テキスト）
6. タイムライン UI
7. Live Activity + 停止導線
8. メタデータ（位置 / モーション / カレンダー）
9. 重要マーク（ウィジェット・Action Button）

**1〜4 まで動けば Phase 2（Mac 側の構造化）に着手できる。** UI は後回しでよい。
