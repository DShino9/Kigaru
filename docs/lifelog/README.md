作成日: 2026-09-03 / ステータス: 構想フェーズ（実装未着手）
想定読者: この構想を引き継いで実装する Mac 上の開発者（Claude Code 含む）

## この構想を一言で

**iPhone を主、在宅時は Mac を副として日常の会話を取りこぼしなく録音し、ローカルで文字起こし・構造化して Obsidian に蓄積する。**
**その蓄積を入力に、5体の AI エージェントが「議事録取得 → 論点構造化 → 並列リサーチ → 戦略統合 → レビュー」を自動実行して戦略レポートを出す。**

元ネタは Notion ベースの 5 エージェント構成（添付スライド）。それを Obsidian に置き換え、かつ入力を「人が渡す議事録」から「勝手に貯まる会話ログ」に変えるのが本構想の狙い。

```
人がやること      = ほぼゼロ（重要マークを押すだけ）
自動で貯まるもの  = 会話ログ・論点・人物・意思決定の履歴
エージェントの入力 = その蓄積
```

## 結論サマリ（意思決定用）

### 作るべきか: 条件付きで Yes

Limitless は 2025年12月に Meta が買収してペンダントを終売、Screenpipe は source-available + 有料化。
**「自分のデータをローカルに持ったまま常時録音する」という選択肢が市場から消えつつある**ため、自作の合理性は 1 年前より高い。

ただし **Phase 0（Mac だけで 1 週間運用）で「本当に読み返すか」を検証してから** iPhone アプリ開発に進むこと。
最大の失敗パターンは「作ったが誰も読み返さない大量のログ」であり、それは 1 週間で判定できる。

### 技術的な結論

| 論点 | 結論 | 理由 |
|---|---|---|
| iPhone の常時録音 | 実現可能（`UIBackgroundModes: audio`） | ただし赤マイクインジケータは常時表示、消せない |
| 電池 | 実測 34〜50% 減 | 日中の充電が必須。VAD で無音を捨てて負荷軽減 |
| 文字起こし場所 | **二段構え**：iPhone 端末内で速報、Mac で正本 | iOS 26 SpeechAnalyzer が日本語・長時間・オンデバイス対応 |
| Mac の ASR | mlx-whisper `large-v3-turbo` を第一候補、kotoba-whisper-v2.0 と実測比較 | Parakeet は日本語非対応なので除外 |
| 話者分離 | pyannote 3.1（mps）| Mac ローカルで実用速度 |
| 保存先 | Vault には構造化ノートのみ。全文と音声は Vault 外 | 数万ノートで Obsidian が重くなるのを回避 |
| 検索 | SQLite FTS5 + ベクタ検索（Vault 外） | Vault のリンクグラフと役割分担 |
| Vault のDB表示 | Obsidian **Bases**（Dataview ではなく） | 5万ノート規模で描画が実用的 |
| エージェント | Claude Code サブエージェント + Workflow | スライドの5ステップをそのまま写像できる |

### 一番の設計上の発見

**「24時間録音」という定義をやめる。**
価値があるのは会議・打合せ・移動中の独り言であって、睡眠中と無音ではない。
VAD（無音検出）で捨てた後の実効録音は 1日あたり 6〜9 時間程度になる。
これを **「取りこぼしゼロの自動録音」** と定義し直すと、電池・ストレージ・処理量のすべてが現実的な範囲に収まる。

### 一番のリスク

技術ではなく **相手のいる会話を常時録音することの社会的リスク**。
日本では一方当事者録音は原則として違法ではないが、それは「訴訟で証拠にできる」という話であって、
「相手に知られたときに関係が壊れない」ことは保証しない。

対処は [08-risks.md](08-risks.md) に詳述するが、設計に組み込むべき最低ラインは以下:

- ワンタップ / ジオフェンス / Focus モード連動の**録音停止機構**
- `privacy: sensitive` なノートは**外部 LLM とWeb検索に一切渡さない**
- 外部に出す前に**固有名詞を仮名化する PII マスキング層**を必ず通す
- 音声は**ローカル完結**（クラウド ASR をデフォルトにしない）
